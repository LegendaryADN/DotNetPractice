# TaskLab

A small, runnable project for teaching .NET and HTTP APIs to beginners. An ASP.NET Core Minimal API serves both a task API and a plain HTML, CSS, and JavaScript frontend from one application.

## Requirements

- The **.NET 10 SDK**, not just the runtime: https://dotnet.microsoft.com/download/dotnet/10.0
- A modern browser (Chrome, Edge, Firefox, or Safari).
- An editor such as VS Code. No extensions are required to run the project.

No Node.js, npm, database, Docker, account, API key, or external NuGet package is required. Icons are bundled locally. Google Fonts is optional: the interface falls back to local fonts without an internet connection.

## Quick start

Open a terminal in the project directory:

```sh
dotnet --version
dotnet run
```

Open **http://localhost:5080**. Keep the terminal running. Press **Ctrl+C** to stop the server. You do not need to start a separate frontend or open the HTML file yourself.

On Windows, this helper also detects the user-local SDK installed for this workspace and selects another port if the default is occupied:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/Start.ps1
```

Use the URL printed in the terminal. `-ExecutionPolicy Bypass` applies to this process only, not the machine's permanent policy. You can also use VS Code's **Terminal > Run Task > Run TaskLab**.

For live reload while changing code:

```sh
dotnet watch run
```

## Try the application

1. Create a task and choose Learning, Practice, or Project.
2. Check its circle to complete it. The counters and completion rate update.
3. Edit its title, category, or completion state.
4. Search by title or switch between task filters.
5. Delete a task and confirm the action.
6. Watch the API activity panel change after each request. It displays the real method, path, status, response body, and elapsed time.

Four example tasks are included. **All data lives in memory. Restarting the process resets the tasks.** Refreshing the browser does not reset them. Multiple browser tabs share the same server data; use Refresh to see changes made elsewhere.

## API reference

| Method | Route | Success | Other expected responses |
| --- | --- | --- | --- |
| GET | `/api/tasks` | 200 + JSON array | |
| GET | `/api/tasks/{id}` | 200 + task | 404 if missing |
| POST | `/api/tasks` | 201 + task + Location header | 400 for invalid input |
| PUT | `/api/tasks/{id}` | 200 + updated task | 400 for invalid input, 404 if missing |
| DELETE | `/api/tasks/{id}` | 204, no body | 404 if missing |

POST and PUT accept this JSON body:

```json
{
  "title": "Make my first HTTP request",
  "category": "Practice",
  "isComplete": false
}
```

`title` must have 1-100 characters after trimming whitespace. `category` must be exactly `Learning`, `Practice`, or `Project` (case-sensitive). `isComplete` is optional and defaults to `false`. PUT supplies the replacement values for all editable fields; it is not a partial PATCH. IDs and creation timestamps are generated by the server.

Validation errors return HTTP 400 with a Problem Details JSON body containing an `errors` object. Malformed JSON or an incompatible JSON type also returns 400. A non-integer ID does not match the `{id:int}` route and returns 404.

Try this in any browser: http://localhost:5080/api/tasks

For command-line requests (use `curl.exe` instead of `curl` in Windows PowerShell 5.1):

```sh
curl http://localhost:5080/api/tasks
```

For POST, PUT, and DELETE, use `TaskLab.http` with an HTTP client such as the optional VS Code REST Client extension, Visual Studio's HTTP editor, or Postman. The application does not require any of these tools.

## Teaching guide

### 1. Understand the platform (10 minutes)

Explain that .NET is the platform, C# is the language, ASP.NET Core is the web framework, and the SDK contains the tools used to build and run the project. Open `TaskLab.csproj`, then run `dotnet build`.

### 2. Follow a read request (10 minutes)

Open `Program.cs` and find `MapGet`. Open `/api/tasks` in a browser. Follow the call to `TaskStore.GetAll()`. Explain a route, an HTTP verb, a resource, JSON serialization, and status code 200. C# uses `Title`; the web JSON defaults serialize it as `title`.

### 3. Create and validate (15 minutes)

Create a task in the UI. Open the browser's developer tools and select Network to inspect the request body and response headers. Find `MapPost`, then `TaskInput.Validate()`. Send the invalid request in `TaskLab.http` and compare 201 Created with 400 Bad Request. Use the Location header to retrieve the created resource.

### 4. Explain services and dependency injection (10 minutes)

Find `AddSingleton<TaskStore>()`. Explain that the framework creates one shared store and supplies it to route handlers. Compare this with constructing a new store on every request. Show records, nullable types, arrays, dictionaries, and the `with` expression. The lock protects shared dictionary operations when requests arrive concurrently.

### 5. Connect the browser to the server (15 minutes)

Find `request()` in `wwwroot/app.js`. Follow `fetch`, `async`/`await`, and JSON parsing. Trace completing a task from a checkbox to PUT and back to the updated interface. Static files and the API share the same origin, so this project needs no CORS configuration. Explain that client validation improves usability, while server validation protects the API even when callers bypass the UI.

### 6. Practice independently (20 minutes)

- Add a fourth category and update the input validation, dropdown, and CSS.
- Add a description field across the model, DTO, store, frontend, and request examples.
- Add `GET /api/tasks/summary` returning total and completed counts.
- Add an optional query parameter to filter completed tasks on the server.
- Replace the in-memory store with SQLite and Entity Framework Core as a follow-up lesson.

Teach the first five sections before adding persistence or authentication. Keep the initial request-response loop easy to follow.

## Verification

Build:

```sh
dotnet build
```

With the app running, open a second terminal and run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/Test-Api.ps1
```

For a different server port:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/Test-Api.ps1 -BaseUrl http://localhost:5081
```

The script checks the frontend, CRUD, response codes, Location header, trimming, validation, malformed JSON, and missing resources. It creates its own task and deletes it afterward. A failed assertion produces a nonzero exit code. This is an HTTP smoke test, not a unit-test framework; `dotnet test` does not run it.

## Troubleshooting

- **`dotnet` is not recognized:** install the .NET 10 SDK and reopen the terminal. For the workspace-local installation, use `scripts/Start.ps1`, or run `& "$env:LOCALAPPDATA\TaskLab\dotnet\dotnet.exe" --info` in PowerShell. That installation does not permanently change PATH.
- **A different SDK is selected:** run `dotnet --list-sdks`. This project targets `net10.0`; older SDKs cannot build it.
- **Port 5080 is busy:** use the Windows helper, or run `dotnet run --urls http://localhost:5081`. Change the base URL in HTTP examples and tests as needed.
- **The API is unavailable:** check that the server terminal is still running and that the browser URL uses the correct port. Click Refresh after restarting.
- **My tasks disappeared:** expected after a server restart, including restarts triggered by `dotnet watch`.
- **Icons or styling are missing:** run from the project directory and visit the server URL, not a `file://` HTML page. The bundled Lucide file must be present in `wwwroot/vendor`.

## Scope and next steps

This is a local teaching application, not a production template. It intentionally has no database, user accounts, authentication, authorization, paging, real-time synchronization, or Swagger UI. The UI inspector, browser Network tab, and HTTP examples are the starting tools for learning the API. HTTP localhost keeps startup simple; production deployments need HTTPS and appropriate security controls. Do not expose this unauthenticated API to the public internet.
